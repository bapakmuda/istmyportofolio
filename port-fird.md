# PORT-RYAN
## Personal Digital Identity — IT Professional

> **Theme:** Terminal / Classified IT Archive / Anonymous-inspired Hacker Aesthetic  
> **Core Concept:** SYSTEM × LIFE

---

# 01. PROJECT VISION

PORT-RYAN adalah personal portfolio website yang menampilkan Ryan bukan hanya sebagai IT Professional, tetapi sebagai seseorang yang:

- membangun sistem
- memecahkan masalah
- bekerja dengan infrastructure & DevOps
- membangun berbagai digital project
- memiliki passion terhadap technology
- merupakan game enthusiast
- memiliki interest terhadap Mio
- memiliki interest terhadap vape

Website tidak dibuat seperti CV tradisional.

Konsep utamanya adalah:

> **A digital identity hidden inside a terminal-style system.**

Pengunjung seolah-olah sedang mengakses sebuah **classified personal archive**.

# 38. MASTER ANIMATION DIRECTION — HACKER / ANONYMOUS-INSPIRED

The visual system should feel like a living terminal rather than a static portfolio. Animation must create the feeling of authentication, data processing, system access, decoding, and archive navigation.

The aesthetic is **Anonymous-inspired**, not an imitation of Anonymous branding. Do not use masks, logos, political symbols, or copyrighted visual identities associated with the group. The design language should come from terminal interfaces, cybersecurity dashboards, CRT displays, code, classified archives, and digital forensics.

## Animation Principles

```text
REALISM > RANDOM EFFECTS
SUBTLE > CONSTANT GLITCH
UX > HACKER EFFECT
PERFORMANCE > ANIMATION
CONTENT > DECORATION
```

Every animation should have a purpose:

- communicate system state
- guide attention
- reveal information
- provide feedback
- create atmosphere

Avoid animation that exists only because it looks "hacker".

# 39. GLOBAL VISUAL EFFECTS

## 39.1 Digital Code Rain

A very subtle background layer consisting of:

```text
01001001
10110100
0x7F4A
> sudo mount /identity
01001110
ACCESS_GRANTED
```

Rules:

- opacity: 3–8%
- slow movement
- randomized content
- never cover important text
- pause/reduce on mobile when necessary
- disable or simplify when `prefers-reduced-motion` is enabled

The code stream should feel like background system traffic, not a Matrix clone.

## 39.2 Scanline

A very thin animated CRT scanline moves vertically across the viewport.

Rules:

- extremely low opacity
- slow movement
- no heavy flicker
- never reduce text readability
- optional on mobile

## 39.3 CRT Grain

Add an almost invisible noise/grain texture to large dark areas.

It should be perceived rather than noticed.

## 39.4 Digital Grid

Use a subtle technical grid behind selected sections:

```text
+----+----+----+----+
|    |    |    |    |
+----+----+----+----+
|    |    |    |    |
+----+----+----+----+
```

The grid can shift slightly according to mouse movement on desktop.

# 58. ACCESSIBILITY / REDUCED MOTION

Respect:

```text
prefers-reduced-motion: reduce
```

When enabled:

- disable code rain
- disable parallax
- disable continuous scanline
- minimize glitch
- replace animated decoding with instant text
- replace typing with short fade/reveal
- keep all content accessible

The portfolio must remain fully usable without animation.

---

# 59. PERFORMANCE BUDGET

Animation must never become the reason the portfolio is slow.

Rules:

```text
CSS transforms preferred
Opacity preferred
Avoid layout thrashing
Avoid unnecessary DOM updates
Avoid huge canvas effects
Lazy-load project images
Lazy-load personal archive images
Use WebP / AVIF where appropriate
Optimize fonts
Minimize JavaScript
```

Animation priority:

```text
P0 — Hero / essential interaction
P1 — Section transitions
P2 — Project interactions
P3 — Background atmosphere
P4 — Easter eggs
```

If performance drops, remove P4 first, then P3.
